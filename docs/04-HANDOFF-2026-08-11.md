## 🕳 กับดักที่เจอจริงในรอบนี้ — อย่าให้กลับมา

### 1. `FormRenderer` เขียน payload ผิดรูปทั้งไฟล์ 🔴

case `'section'` ส่ง `values` ทั้งก้อนให้ช่องลูก ช่องในหมวดจึงถูกเขียน**แบน** (`{tel: …}`)
แต่ validator อ่านแบบ**ซ้อน** (`{customer: {tel: …}}`)

**ผลจริง: ทุกช่องที่อยู่ในหมวดมองไม่เห็นตอนกดส่ง** — ช่างกรอกชื่อลูกค้าครบแล้วยังโดนฟ้อง
ว่าไม่ได้กรอก และเปิดร่างเดิมกลับมาช่องว่างเปล่า ซึ่งคือเกือบทั้งฟอร์ม

เทสต์เดิมมองไม่เห็นเพราะ **สร้าง payload ด้วยมือ** จึงยืนยันได้แค่ว่า validator ตรงกับตัวเอง
นี่เป็นบั๊กตระกูลเดียวกับบั๊ก 4 ในข้อ 2.1 และหลุดมาด้วยเหตุผลเดียวกันเป๊ะ ๆ

> **กติกา: เทสต์ฟอร์มต้องเรนเดอร์ `FormRenderer` จริงแล้วพิมพ์ลงช่องจริง**
> `tests/forms.renderer.test.tsx` คุมไว้แล้ว

### 2. EXIF pointer อ้างอิงคนละฐาน

`readIfd()` รับ offset แบบสัมบูรณ์ แต่ pointer ของ sub-IFD อ้างอิงจากหัว TIFF
ลืมบวก `tiffStart` แล้วอ่านได้ค่าที่ "ดูเหมือนถูก" บางกรณี — เทสต์ที่ประกอบ JPEG เองจับได้

### 3. สลับ driver แล้วไฟล์เก่าอ่านไม่เจอ

ไฟล์ที่อัปตอน `local` อยู่ที่ `./.storage` ไม่ได้ย้ายตาม แถว `Attachment` ยังชี้ key เดิม

การ sign ที่ล้มเหลวเคยอยู่นอก `try/catch` → ตอบ **500** ทั้งที่มันแค่ "ไม่มีไฟล์"
แก้เป็น **404** แล้ว · **ยังไม่มีสคริปต์ migrate ไฟล์เก่า** (ข้อมูลเก่าเป็นแค่เดโม)

### 4. เทสต์เขียนไฟล์จริงตาม driver ที่ `.env` ชี้

พอสลับ `.env` เป็น supabase ทุกครั้งที่รัน `npm test` จะเทไฟล์ทิ้งขว้างเข้า bucket production
ตอนนี้ `vitest.config.ts` pin `local` ไว้เองแล้ว

### 5. React state ยังไม่ flush ในจังหวะเดียวกัน

ตอน `onSign` ถูกเรียก `setPayload` ยังไม่ทันมีผล ต้องประกอบ payload ที่มี key ลายเซ็นเอง
ด้วย `writeSignatureKey()` ก่อนส่งไป hash — ไม่งั้น hash จะครอบฟอร์มที่ยังไม่มีลายเซ็น

## 👉 คนถัดไปเริ่มที่นี่ — 2.5 แอปช่างภาคสนาม

ฟอร์มกรอกได้ครบวงจรแล้ว (ข้อความ · รูปถ่าย · ลายเซ็น) เหลือ 3 อย่าง

1. **ช่างกรอกใบงานจากมือถือได้จริง** — หน้าจอมีแล้ว ต้องลองใช้จริงบนจอเล็ก
2. **ทำงานตอนไม่มีสัญญาณ แล้ว sync ทีหลัง** — ฟอนต์โฮสต์เองไว้แล้วเพื่อข้อนี้
   นี่คือส่วนที่ยากที่สุดของเฟส 2 ที่เหลือ
3. **ปุ่มเปลี่ยนสถานะ** ออกเดินทาง → ถึงหน้างาน → กำลังทำ → เสร็จ

> ⚠️ **บั๊กที่เคยเกิดจริง:** คอลัมน์ `@db.Date` เก็บเป็นเที่ยงคืน **UTC**
> ต้องใช้ `dateOnly()` เทียบเสมอ ถ้าใช้เที่ยงคืนเวลาไทยจะเลื่อนไปวันก่อนหน้าและหาไม่เจอ

**ข้อควรคิดก่อนลงมือทำ offline:** การอัปโหลดรูปกับลายเซ็นตอนนี้ยิงตรงไป
`/api/media/upload` ทันทีที่ถ่าย/เซ็น ถ้าจะทำ offline ต้องคิวไว้ใน IndexedDB แล้วส่งทีหลัง
ซึ่งแปลว่า **`payloadHash` ของลายเซ็นจะถูกคำนวณตอน sync ไม่ใช่ตอนเซ็น** —
ต้องออกแบบให้ hash ยังผูกกับเนื้อหา ณ เวลาที่เซ็นจริง ไม่ใช่เวลาที่เน็ตกลับมา
**นี่เป็นการตัดสินใจเชิงออกแบบ ไม่ใช่รายละเอียดการต่อสาย** คิดให้จบก่อนเขียนโค้ด

## สิ่งที่ผู้พัฒนาต่อต้องรู้ (สรุปจาก roadmap)

- **ค่าที่ลูกค้ายังไม่ยืนยัน เก็บเป็นข้อมูล ไม่ฝังในโค้ด** — ตาราง `AppConfig` · `/settings/assumptions`
- **ชื่อตารางเป็น snake_case แต่ชื่อคอลัมน์เป็น camelCase** — SQL ดิบต้องใส่ `"quotes"`
- **`@db.Date` เก็บเป็นเที่ยงคืน UTC** — ใช้ `dateOnly()` เทียบเสมอ
- **`middleware.ts` รันบน Edge** — ห้าม import `node:crypto` หรือ Prisma
- **`/api/media` ถูกยกเว้นจาก middleware** — route handler ต้องเช็ค session เอง ไม่มีด่านอื่น
- **ห้ามแยกโควตาตามขนาดงาน** — ดู `scheduling.prisma:47-53`
- **การจองต้องกินโควตาเสมอ** — ใช้ `createJobFromBooking()` ไม่ใช่ `createJobFromIntake()`
- **`where: { field: undefined }` ใน Prisma แปลว่า "ไม่กรองเลย"** — เคยลบโควตาหายทั้งตารางมาแล้ว
- **`npm run dev` วัด performance ไม่ได้** — ต้อง `npm run build && npm run start`
