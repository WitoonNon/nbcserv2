## 1. ตั้งเครื่องใหม่

```bash
git clone https://github.com/WitoonNon/nbcserv.git
cd nbcserv
npm install
cp .env.example .env
```

จากนั้น**ต้องขอค่าเหล่านี้จากเจ้าของโปรเจกต์** — ไม่มีอยู่ใน repo และขอผ่านแชทไม่ได้:

| ค่า | เอาไปทำอะไร | หาได้ที่ |
|---|---|---|
| `DATABASE_URL` | ต่อฐานข้อมูล | Supabase → Settings → Database |
| `SUPABASE_SERVICE_ROLE_KEY` | เก็บรูป/ลายเซ็น (เฉพาะถ้าจะใช้ storage จริง) | Supabase → Settings → API |

> ⚠️ **ต้องใช้ pooler ห้ามใช้ direct host** — `db.<ref>.supabase.co` เป็น IPv6-only
> บางเครือข่าย resolve ไม่ได้ ใช้ `aws-0-ap-southeast-1.pooler.supabase.com` เท่านั้น
> พอร์ต `5432` = session mode (migrate/dev/test) · `6543` = transaction mode (Vercel)

**ถ้ายังไม่มี service-role key ก็ทำงานได้** — ปล่อย `STORAGE_DRIVER="local"` ไว้
ไฟล์จะลงดิสก์ที่ `./.storage` ทุกอย่างนอกจากการยิง Supabase จริงทดสอบได้ครบ

```bash
npx prisma generate
npx prisma migrate deploy
npm run db:seed
npm test                  # ต้องได้ 141/141
npm run dev
```

**บัญชีเดโม:** `tech-001@nbcgroup.co.th` (ช่าง) · รหัส `nbc-dev-1234`
`admin@nbcgroup.co.th` เปลี่ยนเป็นรหัสจริงของลูกค้าแล้ว (3 ก.ย. 2569) ขอจากเจ้าของโปรเจกต์

> `db:seed` ล้มด้วย *Connection terminated unexpectedly* ตอนขั้น quota → **รันซ้ำ**
> seed เป็น upsert ทั้งหมด · การ materialise โควตายิง 364 ครั้งเรียงตัวข้าม pooler ไปสิงคโปร์
> จึงมีโอกาสโดนตัดกลางทาง ไม่ใช่ข้อมูลเสีย

## 3. งานถัดไป เรียงตามลำดับที่ควรทำ

### 3.1 🔴 ทำให้บันทึกร่างใบงานกับลายเซ็นใช้ได้ตอนไม่มีสัญญาณ

**นี่คืองานที่เหลือชิ้นใหญ่ที่สุดของเฟส 2** และเป็นการต่อของเดิม ไม่ใช่ออกแบบใหม่ —
โครงสร้างวางไว้หมดแล้ว

ตอนนี้สองอย่างนี้ยังผ่าน **server action** ซึ่ง replay จากคิวไม่ได้
(action id ผูกกับ build ที่สร้างหน้านั้น พอ deploy ใหม่ของในคิวจะยิงไม่ถูกที่)

**ต้องทำ:**

1. เพิ่ม route `POST /api/work-orders/draft` และ `POST /api/work-orders/sign`
   — ลอกโครงจาก `src/app/api/field/advance/route.ts` ได้เลย รวมถึงกติกา status code
2. สลับ `WorkOrderEditor` กับ `SignatureInput` จาก server action มาใช้ `submitOrQueue()`
3. เพิ่ม `'work-order-draft'` และ `'signature'` เข้า `OutboxKind` กับ `senders`
   ใน `src/lib/offline/client.ts` (เคยมีอยู่แล้ว ถอดออกไปเพราะยังไม่มี route)

**แกนที่ยากที่สุดทำไว้ให้แล้ว:** hash ของลายเซ็นคำนวณฝั่ง client ตอนเซ็นจริง
และเซิร์ฟเวอร์ตรวจซ้ำอยู่แล้ว (`signedHash` + `signedAt`) การซิงก์ทีหลังจึงไม่ทำให้
ความหมายของลายเซ็นเสีย — **อย่าเผลอย้ายการ hash กลับไปฝั่งเซิร์ฟเวอร์**

⚠️ **กติกา status code สำคัญกับคิวมาก:**
`5xx / 408 / 429` = ลองใหม่ · `4xx` อื่น = เลิกและแจ้งช่าง
route ที่คืน 500 ให้กับสิ่งที่ควรเป็น 409 จะทำให้คิว retry ตลอดกาล

### 3.2 🟡 Service worker — เปิดแอปตอนไม่มีสัญญาณ

ตอนนี้ "offline" แปลว่า **แท็บที่เปิดค้างไว้แล้ว** ยังกดงานต่อได้
ถ้าช่างรีโหลดหรือเปิดแอปใหม่ตอนไม่มีเน็ต จะเจอหน้า error ของเบราว์เซอร์

ต้องมี service worker แคช app shell + manifest ให้เป็น PWA
ฟอนต์โฮสต์เองไว้แล้วเพื่อข้อนี้โดยเฉพาะ

⚠️ **service worker ที่แคชผิดทำให้แอปค้างเวอร์ชันเก่าแบบกู้ยาก** — ต้องมี version
ในชื่อ cache และล้างของเก่าตอน activate ทดสอบการอัปเดตให้ครบก่อนปล่อย

### 3.3 🟡 รูปที่ยังไม่อัปโหลดยังไม่แสดงรูปย่อ

payload มี key แล้ว แต่ไฟล์ยังอยู่ในคิว รูปย่อจึงยัง 404 จนกว่าจะส่งสำเร็จ
ตอนนี้หน้าจอบอกตรง ๆ ว่า *"รูปเก็บไว้ในเครื่องแล้ว รูปย่อจะยังไม่ขึ้นจนกว่าจะส่งสำเร็จ"*
ซึ่งยอมรับได้ แต่ถ้าจะทำให้ดี ต้องอ่าน Blob จากคิวมาแสดงเป็น `URL.createObjectURL()`

## 5. กับดักที่เสียเวลาไปแล้ว — อย่าเหยียบซ้ำ

### เกี่ยวกับฟอร์ม

- **เทสต์ฟอร์มต้องเรนเดอร์ `FormRenderer` จริงแล้วพิมพ์ลงช่องจริง**
  payload ที่สร้างด้วยมือพิสูจน์ได้แค่ว่า validator ตรงกับตัวเอง
  บั๊กรูปร่าง payload หลุดมาแล้ว **สองครั้ง** ด้วยเหตุผลนี้
  ไฟล์ `.test.tsx` รันบน jsdom ผ่าน docblock `@vitest-environment jsdom`
- **section เก็บเป็น object ซ้อน** (`{customer: {tel: …}}`) ไม่ใช่แบน

### เกี่ยวกับ offline

- **`payloadHash` ต้องคำนวณฝั่ง client ตอนเซ็น** — ย้ายกลับไปฝั่งเซิร์ฟเวอร์เมื่อไหร่
  ลายเซ็นที่ซิงก์ทีหลังจะผูกกับเนื้อหา ณ เวลาที่เน็ตกลับมา ไม่ใช่ที่ลูกค้าเห็น
- **มี implementation เดียว** ใน `src/lib/forms/payload-hash.ts` (Web Crypto)
  เขียนอันที่สองเมื่อไหร่ วันที่มันไม่ตรงกันคือวันที่ลายเซ็นทุกใบกลายเป็น "ถูกแก้"
- **ชื่อไฟล์รูป client เป็นคนตั้ง** และโฟลเดอร์เดือนคิดแบบ **UTC** จาก `capturedAt`
  ถ้าเปลี่ยนให้เซิร์ฟเวอร์ตั้งชื่อ payload จะต้องถูกแก้ตอน sync = hash พัง
- **ออนไลน์ก็ต้องเดินผ่านคิวเหมือนกัน** — เส้นทางที่ทำงานเฉพาะตอนพัง คือเส้นทางที่ไม่มีใครเคยทดสอบ

### เกี่ยวกับเครื่องมือ

- **อย่าใช้ PowerShell แก้ไฟล์ที่มีภาษาไทย** — PS 5.1 `Get-Content -Raw` อ่าน UTF-8
  เป็น ANSI แล้วเขียนกลับ **ทำให้ภาษาไทยพังทั้งไฟล์** (เกิดมาแล้วกับเอกสารสองไฟล์)
  ใช้ editor หรือเครื่องมือที่รู้จัก UTF-8 เท่านั้น
- **โมดูลที่ import `server-only` ต้องมี alias ใน `vitest.config.ts`** — แพ็กเกจจริง
  throw ทันทีที่ถูก import นอก Next
- **`vitest.config.ts` pin `STORAGE_DRIVER=local`** — ต่อให้ `.env` ชี้ Supabase
  `npm test` ก็จะไม่เทไฟล์ทิ้งขว้างลง bucket production **อย่าถอดออก**

### เกี่ยวกับฐานข้อมูล

- **`@db.Date` เก็บเป็นเที่ยงคืน UTC** — ใช้ `dateOnly()` เทียบเสมอ
  ถ้าใช้เที่ยงคืนเวลาไทยจะเลื่อนไปวันก่อนหน้าและหาไม่เจอ
- **`where: { field: undefined }` ใน Prisma = "ไม่กรองเลย"** ไม่ใช่ "ไม่ตรงอะไร"
  เคยลบโควตาหายทั้งตารางมาแล้ว — teardown ของเทสต์ต้องมี `if (id)` ครอบ
- **ชื่อตาราง snake_case แต่ชื่อคอลัมน์ camelCase** — SQL ดิบต้องใส่ `"quotes"`

### เกี่ยวกับ Next

- **`middleware.ts` รันบน Edge** — ห้าม import `node:crypto` หรือ Prisma
- **`/api/media` ถูกยกเว้นจาก middleware** — route handler ต้องเช็ค session เอง ไม่มีด่านอื่น
- **`npm run dev` วัด performance ไม่ได้** — ต้อง `npm run build && npm run start`
