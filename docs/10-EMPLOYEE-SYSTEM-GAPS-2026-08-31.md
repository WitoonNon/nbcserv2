## 🔴 อ่านก่อน: ทั้งหมดนี้ยังไม่เคยรันกับ DB

DB ต่อไม่ได้ทั้งเซสชัน — เขียน · typecheck · build ผ่านหมด แต่
**ไม่มีอะไรในเอกสารนี้ถูกทดสอบกับฐานข้อมูลจริง** โดยเฉพาะการคำนวณเงินเดือน
ที่ตอนนี้อ่านข้อมูลลงเวลาเข้าไปด้วย ซึ่งเป็นทางที่เงินเดินผ่าน

```bash
npx prisma migrate deploy && npx prisma db seed && npx vitest run
```

**`db seed` จำเป็น ไม่ใช่ทางเลือก** — สิทธิ์ใหม่ 4 ตัวมาจาก seed
ถ้าไม่รัน หัวหน้างานจะยังเปิดหน้าลงเวลาไม่ได้ และ **ADMIN จะเปิดหน้าเงินเดือนไม่ได้อีกต่อไป**
(seed prune ให้ตรงลิสต์ — ถอนสิทธิ์เก่าด้วย ไม่ใช่เพิ่มอย่างเดียว)

## ช่องที่ 1 — ต่อระบบลงเวลาเข้ากับเงินเดือน

### ไฟล์ใหม่ `src/modules/hr/worktime.ts` — pure · 17 เทสต์ผ่านแล้ว

จับคู่ IN/OUT เป็น session แล้วนับชั่วโมง · ไม่ต้องมี DB จึงเทสต์ได้เลย

**กฎที่ห้ามแก้โดยไม่เข้าใจ:**

| สถานการณ์ | ทำอะไร | ทำไม |
|---|---|---|
| ลืมกดออก | `problem: 'OPEN'` · **นับ 0 นาที** | เดาเวลาออก = ใส่ชั่วโมงที่ไม่มีใครเห็นลงในเงินเดือน |
| กดเข้า 2 ครั้ง | ตัวแรกเป็น OPEN ตัวที่สองเริ่มใหม่ | ไม่ปิด session ให้เอง |
| กดออกโดยไม่มีเข้า | `ORPHAN_OUT` · นับ 0 นาที | ไม่ทิ้ง — เป็นหลักฐานว่าคนอยู่จริง |
| session > 16 ชม. | `TOO_LONG` · นับ 0 นาที | เท่ากับเพดานโอทีที่มีอยู่เดิม |
| ข้ามเที่ยงคืน | นับเป็นวันที่**เริ่ม** | กะทำงานอยู่นอกสโคป — กฎนี้ไม่ต้องใช้ปฏิทินกะก็จริงได้ |

วันคิดเป็น **วันตามเวลาไทย** ไม่ใช่ UTC (`bangkokDay()`) — กะเช้า 6 โมงคือ
23:00Z ของวันก่อนหน้า ถ้านับแบบ UTC จะไปอยู่ผิดวัน

### 🔴 การตัดสินใจที่สำคัญที่สุดในรอบนี้ — เงินเดือนรายเดือน **ไม่ถูกหักอัตโนมัติ**

[`payroll.service.ts`](../src/modules/hr/payroll.service.ts) — อ่านคอมเมนต์เหนือ `daysWorked`

| ประเภท | ใช้ข้อมูลลงเวลายังไง |
|---|---|
| **รายวัน** | `daysWorked` = วันที่ลงเวลาจริง (จำกัดไม่เกินวันที่ควรทำงาน) |
| **รายเดือน** | ฐานเงินเดือน **ไม่เปลี่ยน** · ขาดงานรายงานเป็น `absentDays` ให้ออฟฟิศตัดสิน |

**เหตุผลที่ไม่หักรายเดือนอัตโนมัติ:** พิกัดจุดสแกนใน DB จริง**ยังผิดอยู่ 4.8 กม.**
ถ้าหักเงินเดือนอัตโนมัติจากข้อมูล geofence ที่ยังผิด = พิกัดผิดค่าเดียว
ตัดเงินเดือนคนทั้งบริษัท นี่เป็นความเสียหายที่ระบบนี้ทำได้มากที่สุด

**เมื่อพิกัดถูกต้องแล้ว และลูกค้ายืนยันนโยบายหักขาดงาน** ค่อยเปลี่ยน —
เป็นการตัดสินใจ ไม่ใช่ค่า default

### ถ้าไม่มีข้อมูลลงเวลาเลย → `attendanceSource = 'CALENDAR'`

งวดที่รันก่อนเริ่มใช้เครื่องลงเวลาจะถูกตีตราไว้ ไม่ให้ปนกับงวดที่วัดจริง
ถ้าไม่มีตรงนี้ เดือนแรกทุกคนจะได้ 0 บาท

### คอลัมน์ใหม่บน `payroll_lines`

`daysPresent` · `minutesWorked` · `absentDays` · `openSessions` · `attendanceSource`

`CalculationSummary` เพิ่ม `absent[]` · `withOpenSessions` · `noAttendanceData`

### ⬜ ยังไม่ได้ทำ — หน้าจอรายงาน

`timesheetFor(employeeId, from, to)` เขียนแล้วใน `timeclock.service.ts`
คืน `{ days, summary }` พร้อมใช้ **แต่ยังไม่มีหน้าจอเรียก**

ใบเสนอราคาข้อ 2 เขียนว่า *"รายงานเวลาทำงานรายบุคคล รายวัน และรายเดือน"*
→ **งานที่เหลือคือทำหน้า `/timesheet/[employeeId]` เรียกฟังก์ชันนี้** ไม่ต้องเขียน logic ใหม่

## ช่องที่ 2 — สิทธิ์หัวหน้างาน + เห็นเฉพาะทีม

### สิทธิ์ใหม่ 4 ตัว ([`prisma/seed/02-rbac.ts`](../prisma/seed/02-rbac.ts))

| สิทธิ์ | ใครได้ | ใช้ที่ |
|---|---|---|
| `hr.approve` | SUPER_ADMIN · ADMIN · **SUPERVISOR** | `/timesheet` · อนุมัติโอที/ลา · ตรวจการลงเวลา |
| `hr.approve.all` | SUPER_ADMIN · ADMIN | ยกเลิกข้อจำกัดเรื่องทีม |

| `payroll.run` | **SUPER_ADMIN เท่านั้น** | เปิด/คำนวณ/ปิดงวด |

`admin.config` กลับไปหมายถึงงานตั้งค่าล้วน ๆ ไม่ใช่ประตูสู่เงินเดือนอีกต่อไป

> ⚠️ **ADMIN เคยเปิด `/payroll` ได้ ตอนนี้เปิดไม่ได้แล้ว** — ตรงกับที่ลูกค้าตอบ
> 26 ส.ค. ว่าเงินเดือนและเลขบัญชี **เจ้าของคนเดียว** ถ้าลูกค้าเปลี่ยนใจ
> ให้เพิ่ม role ใหม่ อย่าขยาย ADMIN

### ไฟล์ใหม่ `src/modules/hr/scope.ts`

`visibleEmployeeIds(user)` → `null` = เห็นหมด · `string[]` = เห็นเฉพาะทีม

**ทีม = crew ที่คนนี้เป็นหัวหน้า** (`Crew.leadTechnicianId`) ไม่ใช่ crew ที่เป็นสมาชิก
คนที่อยู่ทีมเดียวกันคือเพื่อนร่วมงาน ไม่ใช่ลูกน้อง

**หัวหน้าที่ไม่ได้คุม crew ไหนเลย → `[]` = ไม่เห็นใคร ไม่ใช่เห็นทุกคน**
ตรงนี้คือจุดที่พลาดแล้วรั่วทั้งบริษัท

### ตรวจ 2 ชั้นเสมอ

หน้าจอกรองคิว **และ** server action ตรวจซ้ำก่อนเขียน
(`ownerOf()` → `assertMayDecide()` ใน `request-actions.ts`, และใน `actions.ts`)
การซ่อนปุ่มคือการนำเสนอ ไม่ใช่การป้องกัน — หัวหน้าที่รู้ `requestId` ของทีมอื่น
ต้องถูกปฏิเสธตอน POST

## ช่องที่ 3 — อัตราค่าล่วงเวลารายบุคคล

3 คอลัมน์ใหม่บน `employee_wage_changes`:
`otWorkdayMultiplier` · `otHolidayWorkMultiplier` · `otHolidayOtMultiplier` (null ได้)

**อยู่บนตารางประวัติค่าแรง ไม่ใช่บน `Employee`** ด้วยเหตุผลเดียวกับค่าแรง:
เงินเดือนคำนวณย้อนหลัง อัตราที่แก้เดือนกันยาต้องไม่เปลี่ยนสิ่งที่เดือนสิงหาจ่ายไป

`otRatesAtDate(employeeId, on)` อ่านอัตราที่มีผล ณ **วันที่ทำงาน**
`approveOvertime()` ใช้เป็น**ค่าตั้งต้น** เมื่อหัวหน้าไม่ได้พิมพ์ตัวเลข

**ยังกันขั้นต่ำตามกฎหมายเหมือนเดิม** — อัตรารายบุคคลที่ต่ำกว่ากฎหมายถูกดันขึ้นเสมอ
และ `rate()` ปฏิเสธค่าต่ำกว่า 1 เท่าตั้งแต่ตอนบันทึก (ต่ำกว่า 1 คือพิมพ์ผิดทุกครั้ง)
