#### 🔐 ข้อนี้ยกระดับความอ่อนไหวของข้อมูลทั้งระบบ — อ่านให้ครบก่อนแก้

ก่อนหน้านี้ระบบเก็บข้อมูลลูกค้า ตอนนี้เก็บ **เลขบัตรประชาชน เลขบัญชีธนาคาร เงินเดือนรายคน**
คนละชั้นกันตาม PDPA

**กติกา 5 ข้อ ห้ามแก้โดยไม่เข้าใจว่าทำไม**

1. **เลขบัตร/เลขบัญชี เข้ารหัส AES-256-GCM** (`src/lib/crypto/field.ts`)
   IV สุ่มใหม่ทุกค่า — ถ้าใช้ IV ซ้ำ คนที่เห็นตารางจะบอกได้ว่าพนักงาน 2 คนใช้บัญชีเดียวกัน
   โดยไม่ต้องถอดรหัสเลย · GCM ไม่ใช่ CBC เพราะ **ค่าที่ถูกแก้ในฐานข้อมูลต้องถอดไม่ออก
   ไม่ใช่ถอดออกมาเป็นค่าอื่น**
2. **เก็บ 4 หลักท้ายไว้แบบอ่านได้** เพื่อให้ค้นหาและยืนยันกับสมุดบัญชีได้ โดยเลขเต็มไม่ต้องขึ้นจอ
3. **การอ่านปกติไม่คืนข้อมูลอ่อนไหว ทุกระดับสิทธิ์** ถ้าคืนมาโดยอัตโนมัติ
   เดี๋ยวมันไปโผล่ในหน้า list ในล็อก ในแคช แล้วการเข้ารหัสก็ไม่มีความหมาย
4. **`viewSensitive()` เขียนล็อกก่อนถอดรหัส และ `await`** ถ้าเขียนล็อกไม่ได้ = ไม่ให้ข้อมูล
   การอ่านแฟ้มพนักงานที่ไม่ถูกบันทึกคือสิ่งที่ trail นี้มีไว้กันโดยตรง
5. **สิทธิ์แยก 3 ชั้น** `employee.read` / `.write` / `.sensitive`
   หัวหน้าช่างควรรู้ว่าลูกทีมเริ่มงานเมื่อไหร่ แต่**ไม่ควรเห็นว่าใครได้เงินเท่าไหร่**

> **ช่องกรอกเลขบัตรที่ว่างเปล่าตอนแก้ไข = "ไม่แก้ของเดิม" ไม่ใช่ "ลบทิ้ง"**
> ฟอร์มแสดงค่าที่เก็บไว้ไม่ได้ (ต้องถอดรหัส ซึ่งจะทำให้การแก้เบอร์โทรกลายเป็นการอ่านเลขบัตร)
> ช่องว่างจึงเป็นสภาพปกติของการกดบันทึกทั่วไป · มีเทสคุมข้อนี้

## 4. ชั้น raw SQL — ของใหม่ ควรใช้

`src/lib/db/sql.ts`

Prisma ตอบคำถามส่วนใหญ่ได้ดี แต่บางคำถามเป็นของฐานข้อมูล — จัดกลุ่มงานทั้งปีเป็นรายเดือน
ตามเวลาไทย รวมโควตาข้ามโซน ล็อกแถว **raw SQL จึงเป็นเครื่องมือหลัก ไม่ใช่ทางหนี**

```ts
import { query, queryOne, queryValue, sql, all, inList } from '@/lib/db/sql';

const rows = await query<{ month: Date; jobs: number }>(
  sql`SELECT date_trunc('month', "createdAt") AS month, COUNT(*) AS jobs
        FROM "jobs" WHERE ${all([
          sql`"status" <> 'CANCELLED'`,
          zoneId ? sql`"zoneId" = ${zoneId}` : null,
        ])}
       GROUP BY 1`,
  { name: 'jobsByMonth' },
);
```

**3 กับดักที่ชั้นนี้ปิดให้**

1. **BigInt** — `COUNT`/`SUM` คืน bigint และ **`JSON.stringify` throw** ส่งจาก server component
   ไป client แล้วหน้าขาวทั้งหน้า · แปลงให้อัตโนมัติ และ**ปฏิเสธถ้าค่าใหญ่เกินจะแปลง**
   แทนที่จะปัดเศษเงียบๆ (คืนเลขผิดแยกไม่ออกจากทำงานปกติ)
2. **เงื่อนไขที่มีบ้างไม่มีบ้าง** — `all` `any` `inList` · `IN ()` ว่างเป็น syntax error → คืน FALSE
3. **มองไม่เห็นว่า query ไหนช้า** — Prisma มี log ของมัน raw SQL ไม่มี · ตอนนี้มีชื่อ + เวลา เตือนเกิน 250ms

> **ค่าที่ interpolate เข้าไปเป็น bind parameter เสมอ** ไม่ใช่การต่อสตริง
> ยกเว้น `raw()` ที่แปะข้อความตรงๆ — **ห้ามให้ค่าจากผู้ใช้เข้าใกล้มัน**

### 📌 บันทึกความเข้าใจผิดที่แก้แล้ว

comment เดิมใน `quota.service.ts` เขียนว่าการจองล่มเพราะ nested `Prisma.sql` ใน tagged template
กลายเป็น bind parameter · **การจองล่มจริงและแก้แล้วหายจริง แต่กลไกที่บันทึกไว้ไม่ตรง**
ทดสอบบน `@prisma/client 7.9.1` แล้ว — nested fragment, `Prisma.empty`, `Prisma.raw`
ทำงานถูกต้องทั้ง tagged form และ argument form

มีเทสตรึงพฤติกรรมนี้ไว้ใน `tests/db.sql.test.ts` ถ้าอัปเกรดแล้วพังจะรู้ทันที
**สิ่งที่ป้องกันการจองจริงๆ คือเทสที่ครอบทั้งกรณีมีและไม่มี optional condition** —
บั๊กเดิมรอดมาได้เพราะไม่มีเทสไหนส่ง argument ที่ทำให้ branch นั้นทำงาน

## 5. เรื่อง performance — วัดแล้ว อย่าเดา

มีคำถามว่าเว็บกิน CPU หนักไหม **วัดแล้วไม่ใช่**

```
VS Code (7 process)   ~38,800 วินาที
Chrome (3 process)    ~17,000 วินาที
node ทั้งหมดรวมกัน          72 วินาที   ← dev server 60 วินาที ใน 16 นาที
```

**และ Prisma 7 ไม่มี Rust query engine แล้ว** — ต่อผ่าน `@prisma/adapter-pg`
ยิง `pg` ตรงๆ เหมือน Drizzle ทำ · เหตุผลเดิมที่คนหนีจาก Prisma ไม่มีอยู่ในโปรเจกต์นี้
**จึงไม่ควรเพิ่ม ORM ตัวที่สอง** — จะได้ schema 2 ที่ migration 2 ระบบ query 2 สไตล์
โดยไม่ได้ความเร็ว

**ของที่ช้าจริงมี 2 อย่าง ถ้าจะ optimise ให้เริ่มจากนี่**

1. `force-dynamic` **30 หน้า** — ไม่ cache อะไรเลย · แต่เป็น latency ไม่ใช่ CPU
   และหน้าจ่ายงาน/ตารางงานต้องสดจริง เลือกเป็นหน้าๆ
2. **กราฟ 1.4 MB** — CPU ฝั่ง client ตอนวาด canvas · ถ้าจะลด ลดที่จำนวนกราฟ

## 7. กับดักที่เคยกัดมาแล้ว — อย่าเหยียบซ้ำ

| เรื่อง | สิ่งที่เกิดขึ้น |
|---|---|
| **Vercel region** | ฟังก์ชันอยู่ `iad1` DB อยู่สิงคโปร์ → ทุกหน้า 1.7–5 วิ · แก้เป็น `sin1` เหลือ 0.4–0.6 วิ |
| **push แล้วไม่ deploy** | Vercel **ไม่** auto-deploy · ต้อง `npx vercel --prod --yes` |
| **`npm run lint` ใช้ไม่ได้** | เรียก `next lint` ที่ถูกถอดใน Next 16 · ยังไม่ได้ย้ายไป ESLint CLI |
| **`after()` นอก request scope** | โมดูล domain ห้ามพึ่ง request context ของ Next · เรียกที่ route boundary |
| **เทสยิง LINE จริง** | pin driver ใน `vitest.config.ts` แล้ว |
| **`new Date('2026-08-25')`** | คือ UTC เที่ยงคืน = ไทย 7 โมงเช้า · ใช้ `dateOnly()` หรือแยก parts เอง |
| **deleteMany ไม่ใส่ filter** | Prisma ตีความว่า "ทุกแถว" · เคยลบข้อมูลเกินที่ตั้งใจมาแล้ว · ทุก cleanup ในเทสมี guard |
